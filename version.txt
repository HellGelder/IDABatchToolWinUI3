IDA BATCH TOOL (WinUI) — журнал версий сборки
==============================================
Формат записи: версия / дата / что изменилось.
Версия в свойствах exe должна совпадать с последней записью
(IDABatchToolWinUI.csproj: Version / FileVersion, make-portable.ps1: лончер).

1.0.0.19 / 2026-10-21
  Изменено:
  - «Бинарное сравнение»: пары с побайтно идентичными бинарниками (равные
    размеры и содержимое файлов) не подаются на анализаторы вовсе — раньше
    уходили в полный конвейер BinDiff/Diaphora и десятки часов работы при
    известном результате. Для них сразу пишется diff.json со схожестью 100%,
    статус пары в таблице — «идентичен», частный отчёт помечается плашкой
    «Модули идентичны — сравнение анализаторами не проводилось», доанализ
    для таких пар не требуется
  - доанализ (движок BinDiff): в отбор пар «similarity < 99%» не попадают
    и пары, у которых BinDiff не дал ни одной функции, а hexdump-схожесть
    100% (раньше similarity 0 отправляла идентичные файлы на доанализ)
  - доанализ: причина неудачи теперь конкретна — в отчёт пишется, какая
    фаза не состоялась, код выхода процесса и последние строки журнала
    Diaphora (раньше — только «сбой процесса или пустой результат», stderr
    терялся и причину было не установить); плашка в отчёте поменяна с
    «ошибки» на нейтральную «ℹ️», статус пары в GUI честный «ошибка»
    (раньше пара отчитывалась «завершён» при несостоявшемся доанализе);
    при штатном сравнении без новых пар плашка гласит: «Доанализ Diaphora
    дополнительных пар не дал — все совпадения уже найдены BinDiff»
  Исправлено:
  - diff-отчёты: схожести у порога доанализа больше не отображаются как
    «99.0%» при фактических 98.97–98.99% (создавалось впечатление, что
    модули с «99.0%» попали на доанализ вопреки порогу; порог работает
    по полному значению и нарушен не был). Новый аргумент guard фильтра
    процентов: при округлении вверх до ровно 99.0 знаков добавляется,
    пока порог не будет виден честно (98.98%). Затронуто: сводный индекс
    (схожесть, уверенность), «Общая оценка схожести» частного отчёта
  - в разделе «Несопоставленные функции» добавлена развёрнутая сноска
    (3 абзаца): что означает «несопоставленная» функция и почему функции
    без имён (unknown_libname/sub_N/числовые/<unnamed> — нет отладочной
    информации в бинарнике, имя назначено автоматически) часто остаются
    в списке — без имён сопоставление опирается только на сравнение кода,
    и короткие однотипные функции не набирают достаточного совпадения;
    почему одна и та же функция может оказаться в обоих списках (в том
    числе по одному адресу) — «несопоставлена» значит «не сопоставлена
    ни с чем», и это не признак различия; что несопоставленные функции
    не участвуют в расчёте показателя схожести, а сомнительную функцию
    можно открыть по адресу в IDA и сравнить вручную

1.0.0.18 / 2026-10-12
  Изменено:
  - «Бинарное сравнение»: контроль активности Diaphora переведён с одного
    размера БД на два сигнала — ОЗУ процесса (WorkingSet) и размер БД
    (.sqlite + *-wal + *-shm). Зависшим процесс считается только если ОБА
    сигнала не менялись дольше 4 часов (раньше: один размер БД, 2 часа) —
    живой экспорт в долгой фазе без роста памяти больше не рискует быть
    убитым. Пульс показывает ОЗУ основной метрикой: «экспорт N мин,
    ОЗУ X ГБ, БД Y МБ»
  - пульс показывает прогресс экспорта Diaphora: строка «Exported N out of
    M total … remaining time» (идёт в stdout IDA, в Diaphora добавлено её
    дублирование из GUI-диалога) разбирается на лету, в статусе пары —
    «…, 45% (осталось ~12 мин)». Прогресс виден и на диф-фазе не бывает —
    только на экспорте
  Исправлено:
  - diff-отчёты: «Показатель совпадения» и схожести больше не округляются
    до «100.0%» при неполном совпадении (12293 из 12295 → было «100.0%»,
    стало «99.98%»): новый фильтр pct повышает точность, только когда
    округление до 1 знака даёт 100.0/0.0 при неравных значениях. 100.0%
    означает ровно 100%. Действует в парных отчётах и сводном индексе
    (средние, схожесть и hexdump по парам)
  - классификатор модулей: добавлены описания для 9 модулей, остававшихся
    «Неопознанный модуль»: BluetoothAPIs и BthProps (Bluetooth, Windows),
    Normaliz (нормализация Unicode/IDN), USP10 (Uniscribe, отрисовка
    сложных скриптов), ossl_register (объекты статически слинкованного
    OpenSSL), libQt5WebChannel/libQt5WebEngine/libQt5WebEngineCore/
    libQt5WebEngineWidgets (Qt5 WebEngine, Linux)

1.0.0.17 / 2026-10-09
  Исправлено:
  - «Бинарное сравнение»: добавлен контроль фактического прогресса Diaphora по
    размеру БД. Пульс в таблице ранее показывал только прошедшее время и мог
    «идти» часами, когда процесс уже не работал. Теперь каждые 30 секунд
    суммируется размер БД модуля (сам .sqlite + *-wal + *-shm — Diaphora пишет
    в WAL-режиме, рост уходит в -wal). Если БД модуля не меняла размер больше
    2 часов, процесс считается зависшим и убивается, пара завершается ошибкой
    (в таблице и журнале). Живой процесс без ограничения времени — как и прежде
  - пульс теперь показывает и время, и размер БД: «экспорт N мин, БД M МБ» /
    «диф N мин, БД M МБ» — видно, что анализ реально движется
  - доанализ: при неудаче экспорта/сравнения Diaphora в add-JSON пишется
    причина, HTML-отчёт доанализа показывает её баннером «модуль не удалось
    проанализировать» (раньше отчёт выглядел как обычный, только без сопоставлений)

1.0.0.14 / 2026-10-07
  Добавлено:
  - «Git-сравнение»: предварительная проверка контрольных сумм папок перед
    пофайловым сравнением. Наборы файлов (с учётом исключений), их размеры
    и содержимое сверяются побайтово; если папки идентичны (в модульном
    режиме — пара папок каждого модуля), пофайловое сравнение не выполняется:
    все файлы сразу помечаются «без изменений», модуль получает статус
    «без изменений» без создания своей папки. Проверка учитывается и в
    плоском режиме (OLD и NEW идентичны целиком — пустой changes.diff
    без запуска алгоритма Myers). Факт пропуска фиксируется в журнале диффа

1.0.0.10 / 2026-10-07
  Добавлено:
  - «Git-сравнение»: модульный режим — на входе папки, где каждая подпапка
    первого уровня представляет отдельный программный модуль. Дифф строится
    отдельно по каждому модулю (outDir\<модуль>\changes.diff, журнал и частный
    HTML-отчёт рядом), формируется индексный отчёт outDir\git_index.html:
    по каждому модулю — сколько файлов изменено/добавлено/удалено, статус
    и переходы на частный отчёт и changes.diff, строка «Итого». Модуль,
    существующий только с одной стороны, — «удалён целиком»/«новый»; модуль
    без текстовых изменений — строка «без изменений» без папки. Итоги модулей
    сохраняются в modules.json — кнопка отчёта работает и после перезапуска
  - модульное сравнение выполняется в 4 потока (min(4, число модулей)): модули
    делятся на пулы по размеру (крупные вперёд, жадно в наименее загруженный
    пул), каждый поток работает только свой пул; освободившийся поток атомарно
    забирает ещё не начатые модули из оставшихся. Прогресс — карточки потоков
    (текущий модуль, файл N/M) и счётчик «Готово X/N»
  - параметр «Модульное сравнение» с тремя состояниями: включено — всегда
    модульный режим, выключено — всегда плоский (вся папка целиком), частично
    (по умолчанию) — автоматически по наличию подпапок

1.0.0.9 / 2026-10-07
  Исправлено:
  - «Git-сравнение»: дифф не запускался — журнал содержал «ОШИБКА: » и пустую
    строку. Причина: состояние чекбокса «Только исходные коды» читалось внутри
    фоновой задачи (Task.Run), а WinUI запрещает обращаться к элементам UI из
    другого потока (COMException RPC_E_WRONG_THREAD, у которого пустой Message).
    Состояние UI теперь читается до запуска фоновой задачи; то же потенциальное
    место исправлено в генерации HTML-отчёта «Бинарного сравнения»
  - журнал ошибок теперь выводит тип исключения и HResult — пустые сообщения
    больше не скрывают причину сбоя

1.0.0.8 / 2026-10-07
